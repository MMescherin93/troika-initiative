# Тройка! — Стек инициативы

Трекер инициативы для ведущего и игроков, сделанный **по правилам «Тройки!»**
(раздел 5, <https://troika.wishport.online/initiative>) и рассчитанный на
установку в [Owlbear Rodeo](https://www.owlbear.rodeo/).

В «Тройке!» инициатива — это не бросок и не список по возрастанию, а **Стек**:
ёмкость с жетонами, из которой ведущий вынимает жетоны наугад. Этот модуль
считает жетоны, помнит раунды и умеет возвращать жетоны обратно.

---

## 1. Какие правила реализованы

| Пункт правил | Что делает модуль |
| --- | --- |
| **5.1.1** — персонаж получает 2 жетона своего цвета | У каждого персонажа свой цвет жетонов, в Стеке их ровно 2 |
| **5.1.2** — враги добавляют столько жетонов, каково их значение Инициативы | В поле «Инициатива» у врага — столько жетонов и уйдёт в Стек (8 людоящеров с Инициативой 2 = 16 жетонов) |
| **5.1.3** — один жетон уникального цвета, Жетон Конца раунда | Он всегда считается в счётчике и всегда возвращается в Стек |
| **5.2** — ведущий вынимает жетон наугад | Кнопка **«Вытянуть жетон»** выбирает случайный жетон **с учётом количества**: чем больше жетонов, тем чаще выпадает |
| **5.3** — Конец раунда | Выпадает Жетон Конца раунда → раунд +1, все жетоны пересобираются, появляется напоминание про проверки эффектов |
| **5.4** — приспешники дают по одному жетону, все одинаковые | Приспешник добавляет ровно 1 жетон жёлтого цвета |
| **5.5** — вытянув жетон врага, ведущий выбирает любого | Подсказка под жетоном напоминает об этом |
| **6.2.2** — прицеливание | Кнопка **«Прицелиться»**: персонаж берёт свой жетон, при следующем вытягивании показывается **«ДВОЙНОЙ БРОСОК»** — кубики дважды, берём лучший. Прицел **переживает смену раунда** — ровно как в правилах |
| **6.4** — отсрочка | Кнопка **«Вернуть в Стек»** отдаёт вытянутый жетон обратно |
| **7.9.2** — проверки эффектов после Конца раунда | Напоминание выводится в баннере |

Чего в модуле **намеренно нет**: бросков кубиков, автоподсчёта хода, синхронизации
с листом персонажа. Ведущий сам решает, кто действует и что бросает.

---

## 2. Кто чем управляет

- **Ведущий** (роль `GM` в Owlbear Rodeo) — нажимает все кнопки, правит участников.
- **Игроки** (роль `PLAYER`) — видят тот же экран: раунд, вытянутый жетон,
  список участников и их жетоны. Кнопки у них выключены, в шапке написано
  «только просмотр · управляет Ведущий».
- Если ведущего **разжалуют в игрока** прямо во время игры, кнопки
  заблокируются сразу же (слушаем `OBR.player.onChange`).

## 3. Где хранятся данные

| Режим | Когда включается | Хранилище |
| --- | --- | --- |
| **Внутри Owlbear Rodeo** | Страница открыта в iframe Owlbear Rodeo | **Метаданные сцены** — `OBR.scene.setMetadata` |
| **Автономный** | Открыли файл просто в браузере | `localStorage` |

Метаданные сцены выбраны не случайно:

- это **общее** состояние сцены — ведущий меняет, игроки видят сразу;
- игрок, открывший панель **позже**, сразу получает текущий раунд и жетоны;
- данные **переживают** закрытие и открытие окна расширения;
- не нужен отдельный фоновый скрипт и протокол обмена сообщениями.

Ключ, под которым лежит состояние: `com.troika.initiative/state`
(в переписке с OBR принято давать ключам имя в обратном доменном формате,
чтобы расширения не перебивали данные друг друга).

Состояние целиком — небольшой JSON. Его можно **скопировать** кнопкой
«Показать / копировать», сохранить в текстовом файле и позже **загрузить обратно**
кнопкой «Загрузить из текста». Плохой JSON не ломает ничего — просто выводится
подсказка «Это не похоже на JSON».

## 4. Файлы проекта

```
troika-initiative/
├── index.html     разметка: шапка, жетон, кнопки, список, лента
├── styles.css     оформление в стиле troika.wishport.online
├── app.js         вся логика: правила, хранилище, отрисовка
├── manifest.json  описание расширения для Owlbear Rodeo
├── icon.svg       иконка расширения
└── README.md      этот файл
```

### `app.js` разбит на понятные разделы

| Раздел | Что там |
| --- | --- |
| 1. Константы | Ключи хранилища, ссылка на SDK, цвета жетонов |
| 2. Помощники | Округление чисел, защита от зависших вызовов, склонения |
| 3. Состояние | `newState()`, `sanitize()` — проверка любого входного JSON |
| 4. Правила Стека | `tokensFor()`, `rebuild()`, `poolSize()`, снимки для отмены |
| 5. Действия | Вытягивание, отмена, завершение хода, новый раунд, прицел |
| 6. Хранилище | Переключение Owlbear Rodeo ↔ localStorage |
| 7. Экран | `render()` — единственная функция, которая рисует интерфейс |
| 8. Уведомления | Баннер Конца раунда, всплывающие сообщения |
| 9. Обработчики | Все нажатия кнопок |
| 10. Запуск | `boot()` — подключение к OBR и первый рендер |

**Отмена действий** устроена через *снимки*: перед каждым вытягиванием
сохраняется, сколько жетонов было у каждого участника и какой был раунд.
Поэтому «Отменить последнее» возвращает не «примерно», а **точно** то,
что было, включая откат раунда, если случайно вытянули Жетон Конца раунда.

## 5. Как открыть у себя

1. Откройте `index.html` в браузере — расширение работает автономно,
   данные сохранятся в этом браузере.

   > Файл нельзя открывать двойным щелчком (`file://`) — модули JS так не
   > работают. Нужен обычный веб-сервер.

2. Поднять локальный сервер проще всего одной командой в папке проекта:

   ```
   npx serve .
   ```

   или в PowerShell:

   ```powershell
   python -m http.server 8080
   ```

   Затем открыть <http://localhost:8080/>.

## 6. Установка в Owlbear Rodeo

1. Загрузите содержимое папки `troika-initiative/` в публичный репозиторий
   на GitHub (см. раздел 7).
2. Дождитесь, пока GitHub Pages отдаст сайт — проверьте, что адрес
   `https://ВАШ-ИМЯ.github.io/РЕПОЗИТОРИЙ/manifest.json` открывается
   и показывает JSON.
3. В Owlbear Rodeo: меню комнаты → **Extensions** → **Load Extension** →
   вставить адрес манифеста:

   ```
   https://ВАШ-ИМЯ.github.io/РЕПОЗИТОРИЙ/manifest.json
   ```

4. Слева сверху появится иконка — нажмите, откроется панель.

**Чаще всего помогает Ctrl+F5** на странице Owlbear Rodeo: браузер кеширует
манифест на 10 минут, и после любой правки может отдаваться старая версия.

## 7. Пути в `manifest.json` — главный источник проблем

Owlbear Rodeo склеивает **домен** манифеста с путём **без добавления слэша**:

```json
"popover": "/troika-initiative/index.html"
```

даёт `https://домен/troika-initiative/index.html` ✅

```json
"popover": "troika-initiative/index.html"
```

даёт `https://доментроika-initiative/index.html` ❌ — сайт не найден

Поэтому **все пути обязаны начинаться со слэша** и учитывать, что на GitHub
Pages проект лежит в подпапке с именем репозитория:

| Где сайт | Путь |
| --- | --- |
| GitHub Pages (`user.github.io/РЕПО/...`) | `"/troika-initiative/index.html"` |
| Свой домен или корень хостинга | `"/index.html"` |

Текущий `manifest.json` настроен под GitHub Pages.

## 8. Таблица неполадок

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Не найден IP-адрес сервера вроде `...github.ioindex.html` | В манифесте путь без ведущего слэша | Добавить `/` в начало пути |
| Старая версия расширения | Браузер кеширует манифест | Ctrl+F5, удалить расширение, добавить заново |
| Кнопки выключены, в шапке «только просмотр» | Вы подключены игроком, а не ведущим | Роль меняет владелец комнаты |
| «Не удалось сохранить состояние в сцене» | Нет прав на запись в сцену или сцена не открыта | Открыть сцену и проверить, что вы ведущий |
| Ничего не появилось у игроков | Они не открывали панель расширения | Попросите открыть иконку расширения |
| SDK Owlbear Rodeo не загрузился | Нет интернета или заблокирован CDN | Появится предупреждение в консоли; расширение продолжит работать автономно |
